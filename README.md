# dev-rules

AI と一緒にプロダクトを作るときの、共通のルールと手順です。
現在の版：v6（2026-10-18）

## 読む順番
1. common-rules.md：共通のルール
2. task-guide.md：作業ごとの手順
3. 必要に応じて：dynamic-test.md（動的テスト）、adr-template.md（決定の記録）

人間が使うもの：
- prompts.md：チャットに貼る依頼文（P0〜P13）と早見表
- setup.md：新しいプロダクトの準備と、GitHub の設定チェックリスト

## どのファイルが正本か
同じ内容を複数の場所に書かないために、正本を決めています。ほかの場所には「○○を見よ」とだけ書きます。

| 内容 | 正本 |
|---|---|
| ルール、安全、止まるところ | common-rules.md |
| 作業の手順、テスト失敗の切り分け | task-guide.md |
| 動的テストの手順 | dynamic-test.md |
| ADR の書き方 | adr-template.md |
| チャットに貼る依頼文（テスト作成の【前提】を含む） | prompts.md |
| 準備と設定（人間の作業） | setup.md |
| 用語と呼び方 | common-rules.md §0 |

## 版の運用
- ルールを直したら、版を上げ、下の変更履歴に1行書く。
- 各プロダクトの CLAUDE.md には「準拠する dev-rules の版」を書く。版が違うとき、AI は人間に知らせる（勝手に合わせない）。

## 変更履歴
- v6（2026-10-18）：文書の整理を追加（task-guide「文書の整理」、common-rules §5、依頼文 P13）。事実をどの文書に置くかの表を task-guide に置く。整理は人間の依頼でいつでも行い、AI が自発的に行うのは PR の前だけ。
- v5（2026-10-15）：PR は原則作らない（依頼者が依頼したときだけ AI が作る）。PR を作る前に、全ドキュメントを整理する（common-rules §5）。PR の状態はドキュメントに書かず、PR を作った時点で「PR #n（マージ待ち）」と書き、次の PR の整理の時点で前回分を更新する（マージ後の push はしない）。task-guide・prompts の PR 前提の記述を、依頼があったときだけに直す。
- v4（2026-10-14）：PR は作らない方針に変更（作業は枝にコミットして push。取り込みは人間が行う）。人間の指示の優先（common-rules §0-2）を追加。task-guide・prompts・setup・dynamic-test の PR 前提の記述を、枝へのコミットに置き換え。規則変更時の整合性チェックと、範囲を狭めるときの確認を追加（common-rules §5）。
- v3（2026-10-14）：人間の指示を規則より優先する節（common-rules §0-2）を追加。PR を工程ごとの3本から、区切りごとの1本に変更（同時ではなく順番に AI を使う前提）。※task-guide・prompts・setup は、まだ v2 の PR 分割を前提とする記述が残っている（次版で直す）。
- v2（2026-10-14）：PR を工程ごとに 3 本（設計・実装・テスト）にまとめ、報告書は対象の PR のブランチに入れる方式に変更。README と確定項目が食い違うときは確定を正とする規則を追加。adapter の変更範囲を限定。静的レビューの観点5・6を拡張。setup に確認項目を追加。
- v1（2026-10-14）：レビューの指摘を反映。作業の流れ・止まるところ・安全の節、prompts.md、setup.md を追加。静的レビューを7観点に統合。テストの取り込み、テスト失敗の切り分け、adapter 方式を追加。
