## 1. フォルダの構成とモジュール同士のつながり

```
dev-rules/（v13。Markdown のみ）
├── README.md           入口。正本の対応表、読む順番、版の運用、変更履歴
├── VERSION             v13（1行）。プロダクトの作業前の確認が読む
├── claude-md-block.md  各プロダクトの CLAUDE.md に写す部分（作業前の確認・読む先の表・基本の決まり）
├── common-rules.md     全作業で読む核（§0 呼び方〜§8 安全）
├── prompts.md          チャットに貼る依頼文 P0〜P13
├── setup.md            人間の準備と GitHub の設定
├── dynamic-test.md     動的テスト（A・B・C）
├── adr-template.md / spec-template.md   ADR と SPEC の書き方
├── rules/              作業別の手順（design / impl / test / review / maintain / docs-cleanup / sync-product）
└── docs/reviews/       過去の報告書（2026-10-24 の全体レビュー2件）
```

つながり：

1. 各プロダクトの CLAUDE.md（claude-md-block.md の写し）が、作業前に VERSION と版を比べる。一致すれば「基本の決まり」に従い、作業に応じて「読む先の表」の rules/*.md を読む。
2. 全作業で使う核は common-rules.md。枝の名前、別チャット、止まるところ、安全を定める。
3. prompts.md の依頼文は、rules/*.md の見出し、common-rules の節番号、dynamic-test.md を参照する。
4. rules/sync-product.md は、claude-md-block.md から各プロダクトの CLAUDE.md を組み直す（人間が「更新せよ」と指示したときだけ）。
5. 版を上げるときは、VERSION、README の変更履歴、claude-md-block.md、各 CLAUDE.md（雛形の写し）を同じ変更でそろえる。

PR #35 の差分は prompts.md だけで、P7（静的レビュー）の表の行と、「レビューと修正を1回で行う」版（202〜214 行目）を追加している。
