# 保守運用・新機能の追加

## 保守運用（変更を入れるとき）
最初に、変更が次のどちらかを決める。
- 「バグ修正」：ARCHITECTURE どおりに直すだけ。
- 「要件の変更・新機能」：下の「新機能の追加」へ。

テストの有無は、claude-md-block.md「基本の決まり」にある「テストあり」の定義で判断する。

手順：
1. 変更を実装して、枝にコミットして push する（rules/impl.md「実装」）。
2. 実行や出力が変わるときは、README の該当箇所を更新する。
3. テストなし：全体の静的レビュー → 全体の動的テスト（テストなし）。その後、テストを作るかどうかは人間が決める。
4. テストあり：変更分の静的レビュー → 変更分のテスト作成（P5。更新後の README と ARCHITECTURE を貼り、範囲は「変更分」にする）→ テストの取り込み（P6）→ 全体の動的テスト（テストあり）。

## 新機能の追加
1. 要件を整理し、docs/ARCHITECTURE.md を更新する（提案）。「（確定）」済みの項目を変えるときは、ADR（提案）も下書きする。
2. 人間が OK を出して「（確定）」になるまで、実装しない。
3. 実装して、枝にコミットして push する。
4. README を更新する。
5. 変更分の静的レビュー（別のチャット）。
6. 変更分のテスト作成（別のチャット、GitHub なし、P5）→ 取り込み（P6）。
7. 全体の動的テスト。
